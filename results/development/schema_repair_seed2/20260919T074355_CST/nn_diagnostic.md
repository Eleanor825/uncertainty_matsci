# 最小 NN 信息诊断：限定原 train/dev

先回答“标签和特征是否具有可验证的预测信息”，再考虑模型或超参数。**第一阶段全部复用原 train/dev 的已存 proposal、graph、预测、真实 RPC；新增 oracle 0 次、LLM generation 0 次、无需 GPU。** 不改当前冻结方法，不读取 30 个测试体系选择候选，也不对已见差例反复调到正向。

1. **先核标签、时间和支持域。** 按原 train/dev episode 列各 head 的正/负/未知数、有效/缺图数、真正训练 mask 与实测标签来源；核特征只来自 proposal 执行前，未含未来 scientific outcome、RPC 错误或 disposition。`generation_invalid` 是即时 parsing/schema 事件，应先与可直接计算的 parser 一致性比较；`unstable`/`not_new` 是科学评估后的另一时域。缺图只标 unknown，不能把缺图占位向量产生的强预测当成可靠类型标签。只检查原训练 mask/原冻结预测，不回写标签。

2. **防止重复标签造成虚假样本量。** 原 rollout 可把同一次未来 ORB 结果赋给多条此前执行的工具 proposal。预测下一 ORB 事件时，以原 `failure_type_observation_rpc_ids` 归并事件，并报告“每科学事件最后一个已执行 select action”视角；不能把多个重复标签当独立观测。重试中未执行候选没有反事实科学标签。按完整 episode/seed 分组划分，训练和验证不得共享同一 trajectory、prefix 或科学事件；不做随机逐行 CV。

3. **固定小对照核信息与校准，不先扩大搜索。** 先评估现有冻结 NN 与“仅用 train 估计的常数发生率”对照；逐 head、逐支持域报告样本数、覆盖率、Brier/log loss、可定义时的 AUROC/AUPRC，并列固定 .6 下的触发/误报/漏报。若只有一种标签，AUC 记 NA；sample-weight/事件去重规则预先固定。训练内可做按 episode 的固定折数 OOF 诊断；原 dev 作为一次冻结核查，不以它反复选超参。可用固定种子标签置乱作为廉价负对照，保持相同 episode 结构。若缺图/常数发生率已经解释大多数性能，应先承认信息不足，而不是提高网络容量。

4. **只有出现可重复的 dev 信息证据，再诊断控制收益。** 校准改善不自动等于 SUN 改善。预先冻结一个候选及其 unknown 规则，在原 dev 系统上选择明确尚未用于该候选选择的 paired seeds，比同一 checkpoint 下现有控制器与候选；额外候选数、真实 ORB、MACE 和工具预算均单独记录。之后才进入已预注册全 30 体系的新 seed 主评估。此次不启动这个阶段、不改变现有 .6 阈值，也不承诺正向结果。

可继续/停止的最小判断：若正确事件去重、无泄漏、只看有效图后，现 NN 仍无法优于常数对照，现有证据不足以支持 NN 控制收益，应报告缺口；若仅离线指标改善但候选排序/重试没有产生可审计的正确动作差异，也不能宣称完整方法有效。以上均是研究判断建议，不是本报告已完成的新实验。
